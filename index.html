Bare Metal PHP Framework

Introduction

Bare Metal PHP is a lightweight, educational PHP framework built to learn how modern frameworks actually work under the hood. It provides a service container, HTTP kernel with middleware pipeline, routing and controller resolution via reflection, a simple ActiveRecord ORM, query builder, and a tiny Blade-style templating engine.

The goal is not to compete with full-stack frameworks, but to give you a clean, hackable codebase you completely understand.

Philosophy

  • Small, readable code over magical behavior.
  • Feature set mirrors "early Eloquent / early Laravel".
  • Every subsystem is something you can open and modify.
  • Built with PHP 8.2+ features and modern best practices.

Core Features

  • Service container with dependency injection & service providers.
  • Router with parameter binding, named routes & implicit route model binding.
  • View engine with {{ }}, @if, @foreach syntax.
  • Models, relationships, query builder & collections.
  • Database migrations via CLI (php mini ...).
  • Dark-mode debug error page with stack trace & request context.
  • Authentication, sessions, logging & helper functions.
  • Frontend integration (React/Vue with Vite).

Installation

Bare Metal PHP requires PHP 8.2+ with the PDO extension. You can use SQLite (default), MySQL, or PostgreSQL.

Creating a New Project

The easiest way to get started is to use Composer to create a new project: 

composer create-project baremetalphp/baremetalphp my-app

This will create a new directory called my-app with a fresh Bare Metal PHP installation.

Quick Setup

After creating your project, follow these steps:

# 1. Navigate to your project
cd my-app

# 2. Install dependencies (if not done automatically)
composer install

# 3. Create environment file
cp .env.example .env

# 4. Create SQLite database (or configure MySQL/PostgreSQL in .env)
touch database.sqlite

# 5. Run migrations
php mini migrate

# 6. Start development server
php mini serve

Visit http://127.0.0.1:9003 in your browser to see the welcome page!

Edit the .env file to configure your application: 

APP_NAME="My App"

Getting Started

Bare Metal PHP applications start from public/index.php, which boots the application: 

// public/index.php

<?php

declare(strict_types=1);

use BareMetalPHP\Exceptions\ErrorPageRenderer;
use BareMetalPHP\Http\Request;
use BareMetalPHP\Http\Kernel;

require_once __DIR__ . '/../vendor/autoload.php';

// Start session
\BareMetalPHP\Support\Session::start();

$app = require __DIR__ . '/../bootstrap/app.php';

// Build Request from PHP Globals
$request = Request::fromGlobals();

$app->instance(Request::class, $request);

/** @var Kernel $kernel */
$kernel = $app->make(Kernel::class);

$response = $kernel->handle($request);
$response->send();

Routes live in routes/web.php and are automatically loaded by the RoutingServiceProvider. 

// routes/web.php

use BareMetalPHP\Routing\Router;
use BareMetalPHP\View\View;

return function (Router $router): void {
    $router->get('/', function () {
        return View::make('home', ['name' => 'World']);
    });
    
    $router->get('/hello/{name}', function (string $name) {
        return new Response("Hello, {$name}!");
    });
};

Service Container & Bootstrapping

The BareMetalPHP\Application class is a lightweight IoC container. It is responsible for:

  • Registering bindings and singletons.
  • Resolving classes (including constructor injection via reflection).
  • Providing debug info about registered services.
  • Managing service provider registration and booting.
// bootstrap/app.php

use BareMetalPHP\Application;

require_once __DIR__ . '/../vendor/autoload.php';

$app = new Application(__DIR__ . '/..');

// Set instance for global access
Application::setInstance($app);

// Register service providers
$providersFile = __DIR__ . '/providers.php';
if (file_exists($providersFile)) {
    $providers = require $providersFile;
    $app->registerProviders($providers);
}

// Boot all registered providers
$app->boot();

return $app;

Service providers handle all service registration and configuration. See the Service Providers section for more details.

Service Providers

Service Providers are the central place to configure and bootstrap your application. They organize service registration into logical groups and provide a clean, modular way to set up your framework.

Creating a Service Provider

All service providers extend the BareMetalPHP\Support\ServiceProvider base class: 

// app/Providers/AppServiceProvider.php

namespace App\Providers;

use BareMetalPHP\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        // Register bindings in the service container
        $this->app->singleton(SomeService::class, function () {
            return new SomeService();
        });
    }

    public function boot(): void
    {
        // Boot services after all providers are registered
    }
}

Registering Service Providers

Service providers are registered in bootstrap/providers.php: 

// bootstrap/providers.php

return [
    // Framework core providers
    \BareMetalPHP\Providers\ConfigServiceProvider::class,
    \BareMetalPHP\Providers\DatabaseServiceProvider::class,
    \BareMetalPHP\Providers\ViewServiceProvider::class,
    \BareMetalPHP\Providers\RoutingServiceProvider::class,
    \BareMetalPHP\Providers\HttpServiceProvider::class,
    \BareMetalPHP\Providers\LoggingServiceProvider::class,
    
    // Optional: Frontend integration (React/Vue with Vite)
    // \BareMetalPHP\Providers\FrontendServiceProvider::class,
    
    // Application providers
    \App\Providers\AppServiceProvider::class,
];

Built-in Service Providers

The framework includes several service providers:

  • ConfigServiceProvider – Loads configuration files from config/
  • DatabaseServiceProvider – Registers database connections (SQLite, MySQL, PostgreSQL) and model setup
  • ViewServiceProvider – Configures view paths and caching
  • RoutingServiceProvider – Registers router and loads route files
  • HttpServiceProvider – Registers HTTP kernel
  • LoggingServiceProvider – Sets up logging system
  • FrontendServiceProvider – Optional provider for React/Vue integration with Vite
tip

Service providers are registered in order, and all register() methods are called before any boot() methods. This ensures dependencies are available when booting.

HTTP Kernel & Middleware

The HTTP layer consists of:

  • BareMetalPHP\Http\Request – an immutable request object.
  • BareMetalPHP\Http\Response – simple response wrapper.
  • BareMetalPHP\Http\Kernel – builds a middleware pipeline and delegates to the router.
// Kernel::handle()

public function handle(Request $request): Response
{
    try {
        $pipeline = array_reduce(
            array_reverse($this->middleware),
            function (callable $next, string $middlewareClass) {
                return function (Request $request) use ($next, $middlewareClass): Response {
                    $middleware = $this->app->make($middlewareClass);
                    return $middleware->handle($request, $next);
                };
            },
            fn (Request $request): Response => $this->router->dispatch($request)
        );
        return $pipeline($request);
    } catch (\Throwable $e) {
        // Handle exceptions with error pages or API responses
    }
}

Middleware are simple classes with a handle(Request $request, Closure $next) method. 

// app/Http/Middleware/CustomMiddleware.php

namespace App\Http\Middleware;

use BareMetalPHP\Http\Request;
use BareMetalPHP\Http\Response;
use Closure;

class CustomMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        // Before the request is handled
        $response = $next($request);

        // After the request is handled
        return $response;
    }
}

Middleware can be registered globally in BareMetalPHP\Http\Kernel::$middleware or applied to specific routes.

Routing & Controllers

Basic Routes

// routes/web.php

return function (Router $router): void {
    $router->get('/', function () {
        return View::make('home');
    });

    $router->get('/hello/{name}', function (string $name) {
        return new Response("Hello, {$name}");
    });
    
    $router->post('/users', [UserController::class, 'store']);
};

Named Routes

Routes can be given names for easy URL generation:

$router->get('/users/{id}', [UserController::class, 'show'])->name('users.show');

// Generate URL using the route helper
$url = route('users.show', ['id' => 1]);
// Returns: /users/1

Controller Actions

Routes can point to controllers using array syntax:

$router->get('/dashboard', [HomeController::class, 'index']);

// In HomeController
namespace App\Http\Controllers;

use BareMetalPHP\Http\Request;
use BareMetalPHP\Http\Response;

class HomeController
{
    public function index(Request $request): Response
    {
        // Request is injected automatically via reflection
        return View::make('dashboard');
    }
}

Route Parameters & Implicit Model Binding

Named parameters in routes are converted into regexes and collected into $routeParams. These are used both as raw values and for implicit route model binding. 

$router->get('/users/{user}', [UserController::class, 'show']);

// In UserController

public function show(\App\Models\User $user): Response
{
    // The {user} parameter is resolved into a User model:
    // SELECT * FROM users WHERE id = :id LIMIT 1
    return View::make('users.show', compact('user'));
}

Under the hood, the router uses reflection to check if a parameter type is a subclass of BareMetalPHP\Database\Model and the parameter name matches a route parameter; if so, it calls User::find($id) and injects the model.

Views & Templating

Views live in resources/views and are compiled to PHP into storage/views by BareMetalPHP\View\TemplateEngine. The View class compiles and returns a Response.

Template Syntax

  • {{ $var }} – escaped echo (htmlspecialchars).
  • {!! $html !!} – raw echo (use with caution!).
  • @if, @elseif, @else, @endif.
  • @foreach, @endforeach.
<!-- resources/views/home.php -->

<!doctype html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Bare Metal PHP • Home</title>
</head>
<body>
    <h1>Welcome, {{ $user->name }}</h1>

    @if ($user->posts->isEmpty())
        <p>No posts yet.</p>
    @else
        <ul>
            @foreach ($user->posts as $post)
                <li>{{ $post->title }}</li>
            @endforeach
        </ul>
    @endif
</body>
</html>

The first time a view is requested, it is compiled and cached; subsequent requests use the cached file until the source template timestamp changes.

Using Views in Controllers

use BareMetalPHP\View\View;

public function index(): Response
{
    return View::make('home', [
        'name' => 'World'
    ]);
}

// Or using the helper function
return view('home', ['name' => 'World']);

Database Configuration

The framework supports multiple database drivers: SQLite, MySQL, and PostgreSQL. Database configuration is managed through config/database.php and environment variables.

Configuration File

The config/database.php file defines all available database connections: 

return [
    'default' => env('DB_CONNECTION', 'sqlite'),
    'connections' => [
        'sqlite' => [
            'driver' => 'sqlite',
            'database' => env('DB_DATABASE', database_path('database.sqlite')),
        ],
        'mysql' => [
            'driver' => 'mysql',
            'host' => env('DB_HOST', '127.0.0.1'),
            'port' => env('DB_PORT', 3306),
            'database' => env('DB_DATABASE', 'forge'),
            'username' => env('DB_USERNAME', 'forge'),
            'password' => env('DB_PASSWORD', ''),
            'charset' => env('DB_CHARSET', 'utf8mb4'),
        ],
        'pgsql' => [
            'driver' => 'pgsql',
            'host' => env('DB_HOST', '127.0.0.1'),
            'port' => env('DB_PORT', 5432),
            'database' => env('DB_DATABASE', 'forge'),
            'username' => env('DB_USERNAME', 'forge'),
            'password' => env('DB_PASSWORD', ''),
            'charset' => env('DB_CHARSET', 'utf8'),
        ],
    ],
];

The framework automatically handles driver-specific SQL differences (identifier quoting, LIMIT/OFFSET syntax, boolean types, etc.) so your code works across all supported databases.

Models & ActiveRecord

Models extend BareMetalPHP\Database\Model and map to database tables. The base model provides:

  • ActiveRecord operations: save(), delete(), all(), find().
  • Magic attributes via __get/__set and accessor/mutator methods.
  • Timestamps (created_at, updated_at).
  • Relationship helpers: hasOne, hasMany, belongsTo, belongsToMany.
// app/Models/User.php

namespace App\Models;

use BareMetalPHP\Database\Model;

class User extends Model
{
    protected static string $table = 'users';

    public function posts()
    {
        return $this->hasMany(Post::class, 'user_id');
    }

    // Accessor example:
    public function getDisplayNameAttribute(): string
    {
        return $this->name . ' <' . $this->email . '>';
    }

    // Mutator example:
    public function setEmailAttribute(string $value): void
    {
        $this->attributes['email'] = strtolower($value);
    }
}

Creating & Updating

// create
$user = new User([
    'name'  => 'Elliot Anderson',
    'email' => 'elliot@example.com',
]);

$user->save();        // INSERT, sets $user->id

// update
$user->name = 'New Name';
$user->save();        // UPDATE users SET ... WHERE id = :id

Attributes are available directly as properties thanks to magic attribute handling and relationship resolution:

$user = User::find(1);

echo $user->display_name;   // calls getDisplayNameAttribute()
echo $user->posts->count(); // posts() relationship, wrapped in a Collection

Query Builder & Collection

The BareMetalPHP\Database\Builder class provides a fluent query builder for SELECT queries. Results are wrapped in BareMetalPHP\Support\Collection, an iterable helper with map, filter, first, pluck, and more. 

// Fluent builder usage

$users = User::query()
    ->where('age', '>', 18)
    ->where('status', 'active')
    ->orderBy('name')
    ->limit(10)
    ->get();           // returns Collection<User>

$names = $users
    ->map(fn (User $u) => $u->name)
    ->all();

Models provide shortcuts that delegate to the builder: 

User::all();                        // Collection<User>
User::find(1);                      // ?User
User::where('status', 'active')->get();    // Collection<User>
note

The builder automatically adapts SQL syntax for SQLite, MySQL, and PostgreSQL. It handles identifier quoting, LIMIT/OFFSET syntax, and data type differences automatically.

Migrations & Console Commands

Available commands:

  make:controller
  make:migration
  migrate
  migrate:rollback

Creating & Running Migrations

// generate a migration class under database/migrations
$ php mini make:migration create_users_table

The generated file returns an anonymous class extending BareMetalPHP\Database\Migration with up() and down() methods: 

// database/migrations/20241204120000_create_users_table.php

use BareMetalPHP\Database\Migration;
use BareMetalPHP\Database\Connection;

return new class extends Migration {
    public function up(Connection $connection): void
    {
        $connection->pdo()->exec(<<<SQL
CREATE TABLE users (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,
    email       TEXT NOT NULL,
    password    TEXT NOT NULL,
    created_at  TEXT,
    updated_at  TEXT
);
SQL);
    }

    public function down(Connection $connection): void
    {
        $connection->pdo()->exec('DROP TABLE IF EXISTS users;');
    }
};
// run outstanding migrations
$ php mini migrate

// rollback most recent batch
$ php mini migrate:rollback

Authentication

Bare Metal PHP includes a simple authentication system using sessions. The BareMetalPHP\Auth\Auth class provides methods for user authentication.

Authenticating Users

use BareMetalPHP\Auth\Auth;

// Attempt to authenticate with email and password
$user = Auth::attempt($email, $password);

if ($user) {
    // User is now logged in
    return redirect('/dashboard');
} else {
    // Authentication failed
    return redirect('/login')->with('error', 'Invalid credentials');
}

// Manually log in a user
Auth::login($user);

// Log out
Auth::logout();

// Check if user is authenticated
if (Auth::check()) {
    $user = Auth::user();
}

// Get authenticated user
$user = Auth::user();

// Get authenticated user ID
$userId = Auth::id();

Using in Controllers

// app/Http/Controllers/LoginController.php

public function login(Request $request): Response
{
    $user = Auth::attempt(
        $request->input('email'),
        $request->input('password')
    );

    if (!$user) {
        return redirect('/login');
    }

    return redirect('/dashboard');
}

// Using the helper function
use function auth;

$user = auth(); // Returns the authenticated user or null

Sessions

Sessions are managed through the BareMetalPHP\Support\Session class. Sessions must be started in your public/index.php file.

Session Usage

use BareMetalPHP\Support\Session;

// Start session (in public/index.php)
Session::start();

// Set a session value
Session::set('key', 'value');

// Get a session value
$value = Session::get('key');

// Check if session has a key
if (Session::has('key')) {
    // ...
}

// Remove a session value
Session::remove('key');

// Get all session data
$all = Session::all();

// Regenerate session ID
Session::regenerate();

Helper Function

// Using the session helper
session('key', 'value');        // Set
$value = session('key');        // Get
$all = session();               // Get all

Logging

Bare Metal PHP includes a logging system that writes to files in storage/logs. The logging service provider automatically configures the log path.

Logging Messages

// Different log levels

Log::alert('Action must be taken immediately');
Log::critical('Critical conditions');
Log::error('Error occurred');
Log::warning('Warning message');
Log::notice('Normal but significant condition');
Log::info('Informational message');
Log::debug('Debug-level message');

// With context
Log::error('User login failed', [
    'user_id' => 123,

Helper Functions

// Using helper functions

Frontend Integration

Bare Metal PHP includes optional support for modern frontend frameworks (React and Vue) with Vite for hot module replacement and asset bundling.

Installation

Install frontend integration using the CLI command: 

# Install React
php mini frontend:install react

This will create the necessary files and configuration. Then: 

# Install Node.js dependencies
npm install

// Render an SPA component

Error Pages & Debug Experience

In debug mode (APP_DEBUG=true), unhandled exceptions are rendered using BareMetalPHP\Exceptions\ErrorPageRenderer – a dark error page that shows:

  • Exception class, message, file and line.
  • Code excerpt with the failing line highlighted.
  • Stack trace with "App" vs "Framework" frames.
  • Request context: method, URI, client IP and superglobals (GET, POST, cookies, headers).
  • Container bindings: registered bindings, singletons and instances.
  • A saved HTML snapshot link under public/debug/<id>.html.

API requests (routes starting with /api/) automatically receive JSON error responses: 

{
    "error": "Internal Server Error",
    "message": "Error message here",
    "file": "path/to/file.php",
    "line": 42,
    "trace": [...]
}
production

In production, set APP_DEBUG=false. The kernel will return a generic 500 Internal Server Error response without exposing stack traces or request data.
